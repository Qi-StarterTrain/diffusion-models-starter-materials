## 三、核心架构

```
Image (multi-camera)
   ↓
PaliGemma 3B (VLM backbone)
   ↓ + language instruction
Multi-modal embedding
   ↓
Action Flow Matching Head (~300M)
   ↓
Action trajectory ∈ R^{H × A}  (H=50 future actions)
```

- **Backbone**：PaliGemma 3B（pretrained Google VLM）
- **Action head**：Flow Matching network，~300M params
- **Action**：50 个未来时间步的 trajectory（不是单步）

## 四、Flow Matching for Action

### 4.1 训练 loss

$$\mathcal{L} = \mathbb{E}_{t, A_{\text{gt}}, \epsilon}\left[\|v_\theta(A_t, t, \text{vision}, \text{lang}) - (A_{\text{gt}} - \epsilon)\|^2\right]$$

其中 $A_t = (1-t) \epsilon + t A_{\text{gt}}$（linear path）。

—— **就是 rectified flow** 的形式（参考 L12, derive_07）。

### 4.2 推理

```python
def policy_step(observation, language):
    A_t = randn(50, 7)
    for i in range(4):  # 仅 4 步 FM
        t = i / 4
        v = action_head(A_t, t, vision_feat, lang_feat)
        A_t = A_t + v * (1/4)
    return A_t  # 50 步 action trajectory
```

**4 步 FM 完成 sampling**。4 ms/step × 4 = 16 ms 总耗时 → 60 Hz。

## 五、Action Chunking

Pi-0 一次性生成 **50 步未来 action**。
- 每次 inference 产出 50 步 plan
- Execute 前 K 步（如 K=10）
- K 步后重新规划

**类比**：人不是每秒决定走哪只脚，而是想"接下来 1 秒内的步伐"。Action chunking 让模型 plan ahead。

实证：chunking 比单步预测在长时序 task 上成功率高 30%+。

## 七、实验

Pi-0 在多个 dexterous 任务上击败 OpenVLA 和 Octo：

| Task | OpenVLA | Pi-0 |
|------|---------|------|
| 叠衣服 (folding) | 20% | 70% |
| 拆装乐高 | 0% | 60% |
| 餐桌整理 | 30% | 85% |
| 长时任务 (30s+) | 5% | 40% |

—— 在**复杂操纵** task 上压倒性优势。

## 八、为什么 FM 适合 action

1. **少步采样**：4 步 vs DDPM 50 步 → 实时控制可行
2. **连续 action 自然**：trajectory 是连续的，FM 直接处理（不需要 discrete tokenization）
3. **训练简洁**：linear path + MSE，没有复杂 schedule
4. **多模态自然**：同 obs 下多个合理 action，FM 通过 stochastic init 给出多样

## 九、Pi-0 vs OpenVLA 对比

| | OpenVLA | Pi-0 |
|---|---------|------|
| Action 形式 | Discrete token | FM-generated trajectory |
| Inference 频率 | 3-10 Hz | 50-100 Hz |
| 强项 | Language grounding | Real-time control |
| 弱项 | 慢 | 长 horizon 规划 |
| 训练数据 | Open X-Embodiment 970K | PI 自有 10000 hr + Web |
| 开源 | 全 | 部分（research checkpoint） |

→ **两者互补**：可能未来融合（FM action head + LLM-style grounding）。

## 十、常被误读

### 1. "Pi-0 = OpenVLA 换 FM action head?"
**简化是**，但工程细节远多：data scale、PaliGemma backbone 选择、action chunking 设计、co-training 策略等。

### 2. "Pi-0 能 zero-shot 任意 robot?"
**部分**。强 generalization 到训练见过的 embodiment；新 robot 仍需 fine-tune（PI 没公开 LoRA 方案）。

### 3. "Pi-0 完全开源？"
**否**。代码 + research checkpoint 开源，但**完整 model + 数据**未公开（商业 moat）。

## 十一、对国内研究的启示

1. **数据是命门**：Pi-0 的优势 30% 来自算法，70% 来自数据规模 → 国内具身公司（智元、宇树、宇树）也在 collect 万小时级数据
2. **FM 是新主流**：DDPM 路线在 action gen 上几乎被 FM 替代
3. **Backbone 选择**：用 LLM/VLM（如 Qwen-VL）作 backbone 是趋势

## 十二、思考题

1. 为什么 Pi-0 用 50 步 chunk 而不是 100 步？设计 ablation
2. 实现一个简化 Pi-0：VLM backbone (Qwen-VL) + FM action head + 1000 demos
3. Pi-0 的 50 步 trajectory 是固定时间长度还是固定步数？哪个更合理？
4. 思考：Pi-0 + LCM 蒸馏到 1 步采样可行吗？挑战在哪？
